# 刀文AI商业·直播知识蒸馏

把直播间的连麦拆解与商业讨论整理成脱离直播也能读懂、可核对的实战案例。聚焦**AI商业变现、公域流量矩阵、私域高客单转化、实体赋能与轻量化团队交付**，保留具体漏斗链路、客单价条件、团队分工与失败预警，不把商业测算写成既成事实，也不把案例抽空成口号。

## 内容组织与保真边界

- **全量去向与边界隔离**：全部有价值的行业案例、获客链路、报价结构、团队交付模式、失败与现金流约束均须有去向；不同连麦者、客户与赛道保持独立边界，同一案例的前后补充可合并，不强行跨案例拼凑故事。章节数、字数和清单数不作硬性要求。
- **漏斗结构按原文保全**：围绕`流量入口 -> 私域承接 -> 产品包装/报价 -> 交付与团队配置 -> 风险/失败边界`组织内容；原文未讨论到的环节允许缺项，严禁为填满结构而补写转化率、客单价、分润比例或财务预测。详见 [funnel-structure.md](references/funnel-structure.md)。
- **推销过滤与经营指标分离**：纯引流、催单、买课与加群口播物理剔除，不进入正文；若推销或招商段中夹带真实转化率、定价逻辑、沙龙门槛、获客成本或交付边界等实质经营指标，必须剥离话术并保留实质信息，raw只读，过滤去向另记台账。详见 [ad-filtering.md](references/ad-filtering.md)。
- **严格区分实绩与口头测算**：目标转化率、心算营收、假设补贴、意向存量资源（如“有4000家存量客情，已做5家”）与已到账收入必须明确写清阶段与口径；建议报价不改成已成交实绩，示例分润不写成通用行规。
- **事实核查与白话可读**：共用 [可读性规则](../qizhi-ai-distill/references/readability.md) 与 [事实强度检查](../qizhi-ai-distill/references/readability.md#五事实强度与具体细节检查)；用白话讲清商业逻辑与行业潜规则，保留有信息的反问与分歧，不附内部编号或底部录制说明。

## 执行流程

1. **确认范围与运行配置**：先读项目 `WORK_STATE.md`、适用队列与 `docs/distillation-runtime.md`，核对当前 plan、owner、raw 与 review 差集；已有计划只 resume，不重复启动 worker。
2. **源与转写核验**：按共用的 [录制与恢复原则](../qizhi-ai-distill/references/operations.md) 核查录制记录、邻段归属、音轨与瞬断合并（如跨片合并需有录制依据）；raw 与原音频只读，不因缓存清理重跑 ASR。
3. **长场分批阅读与提取**：新场、重建与遗漏复核执行共用的 [长场分批保全协议](../qizhi-ai-distill/references/long-session-workflow.md)：逐块完整读当前有效 plan 的全部 raw 与已存弹幕，逐批记录具体案例、数字口径与未完关系，再按案合稿；分派与摘要不等于已读。
4. **纠词、过滤与成文**：依项目审核流程逐处确认纠词与术语（如工具名、行业简称），按 [ad-filtering.md](references/ad-filtering.md) 记录广告过滤去向；按 [funnel-structure.md](references/funnel-structure.md) 组织案例，保留前提条件、失败案例与合作边界。
5. **双向核查与交付**：集成作者完整通读提取稿、最终正文与实质 diff；独立审核或第二轮回读原文与弹幕，查漏同时反向核对正文无无据新增的数字、比例或因果，绑定最终正文 hash。按项目授权范围构建、发布并实际 GET 验收；有效新经验回写项目 Skill 或运行文档，不写个人记忆。

## 项目接口与维护边界

状态、队列、并发数、站点分类、CTA 及临时授权由项目维护，入口见 `docs/distillation-runtime.md`。本 Skill 只保留稳定方法、领域边界与规范文件，不保存实时进度或历史部署流水。
