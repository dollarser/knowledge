# 长场直播：分批提取、交接、合稿与保全

适用于 Antigravity、Codex 或其他执行者处理新直播、全面回源重建、全原文遗漏复核。局部校字/排版只核受影响原段。主题数和字数不是合格线；少量大主题可以容纳许多完整案例，但不能用几段总论替代具体经验。

## 1. 冻结输入与阅读计划

核当前plan、raw、已存弹幕及hash。以当前有效子块替代旧父块；新产出的raw及时进入待审差集。按实际上下文容量划批，不按固定小时、行数或案例数切配额。记录批次的chunk与1基segment范围、弹幕ID、实际已读范围、源hash及未完讨论；输出截断必须补读。

阅读视图可以省掉请求元数据、重复JSON字段和空白，不删除任何发言文本、单字确认/否定、反问、异常标记或边界。不把摘要称为“事实脱水”。每段保留稳定原段定位；同一块的speaker编号也只提供局部线索，不按编号跨块聚合身份。词典仅提出候选，阅读视图不自动替换名称。清理工具不能把听不清或静音标签消失解释为已恢复音频。

生成阅读视图前核对实际文本字段：顶层`text`缺失或为空时，仍须检查并读取全部`segments[*].text`；两者都有内容时核对是否一致，差异保留并查明。不能把字段缺失当作没有对话，也不能因清理稿较短就认定原文已读完。覆盖记录应写明实际读取字段和段数。

## 2. 每批先做具体提取，不先写全场摘要

完整读完本批，保存详细提取稿与条目台账；格式可沿用现有审计JSON/Markdown，不另造重复台账。每条有价值内容至少能表达：

- 稳定item_id、case_id或独立议题标识，以及原chunk/segment或弹幕ID；人物未确认时保持局部身份。
- 具体内容：原文实际讲到的问题、动作、工具用途/输入输出/人工步骤、获客渠道/转化动作、价格与收费周期、成本回款、结果失败、限制和反例。只填已讲内容，不要求每项齐全。
- 业务阶段及重要原词：已做、建议、设想、报价假设、未成交、后续纠正不能混用。金额/单位/否定及会改变结论的原句留定位。
- 与前批同案的补充或冲突、未完问答、需要后批核实的关系。

只记“谈了AI获客”“推荐Codex”不算提取完成；需保存当场具体用法。原文仅报工具名时可如实短记，不能补造教程。短经验和弹幕独有补充不必挂靠大项目。

## 3. 持久交接，防止上下文压缩丢知识

批次结束或上下文切换前落盘：精确阅读覆盖、详细提取稿/台账、跨批未完案例及下一差集。交接摘要只导航到这些文件，不能取代它们；新执行者先读详细产物及必要边界原文，不从上一轮短摘要重新概括。继承已读记录先核源hash，不能把分派、导入或读取文件名记作全文已读。

## 4. 按案例合稿，再安排主题导航

集成作者完整读所有批次的详细提取稿、全部条目与边界待办，按同一人物/客户/项目组织案例。大主题下可以分多个案例或小节，保留各自工具、数字、动作和失败；不得因同属获客/管理/AI而拼成人物故事或压成统一结论。

跨批确认同案后合并补充；不同条件、反例和后续变化保留。去重只去真正重复的陈述，不删除第二次新增的约束或做法。全文重写时保留旧条目/旧章节到新位置的去向。不能先规定5或10个主题，再削减内容去适配目录。

## 5. 逐项验收，而非凭文章看起来完整

复用现有工具/经验台账，为每个有价值item记录最终章节和具体段落/短引文，或明确排除理由。只指向“商业模式”章标题、只出现工具名称、只有抽象观点不算保留具体用法。合并项列出被合并ID及新增细节去向；不以“已覆盖”笼统勾选。

独立审核者或明确分开的第二轮回读全部原文与已存弹幕，核正文未漏案例、工具操作、获客运营、账本、试错和反例；同时反向检查正文有无原文未讲的动机、步骤、数字和结果。问题返回提取稿补齐，再核实质diff。集成作者读完整最终稿，绑定正文hash；后续修改重核受影响项。

有价值item未落到具体正文、未完案例未处理、阅读差集非空时，不能完成知识验收。没有新增价值的段落可以省略，但记录原因；不能以篇幅、主题数、出现关键词、构建或GET通过代替语义审核。部署验收仍按现有独立流程执行。
